# chat-jev 浏览器扩展（Chrome）

把 chat-jev 的「读一句话 → 判断意图/风险 → 给行动建议」搬进浏览器侧边栏，
用来读 WhatsApp Web、Telegram Web、Slack、Discord、Teams 等网页版聊天。

**只读，从不代发**：这个扩展只读页面上已经显示的文字，绝不修改页面、绝不往输入框写字、
绝不帮你按发送。第 1/2 期还没有「填入候选」这个功能，只有分析结果和诊断信息。

**当前只有通用启发式适配器**：还没有针对某个站点专门写的解析逻辑，靠的是「找一个消息容器
+ 气泡左右位置」这类通用规则。在结构清晰的站点上大致能用，在别的站点上可能读不到消息、
或者分不清哪句是对方发的——这是预期之内的，不是 bug。见下面「诊断视图」一节：
这正是用来收集真实站点结构、后续写专用适配器的机制。

## 装扩展

需要 Node.js（跟仓库其他 TypeScript 部分一致）。

```bash
cd extension
npm install
npm run build
```

`npm run build` 会在 `extension/dist/` 下产出可加载的扩展：`manifest.json`、
`background.js`、`content.js`、`panel/index.html`、`panel/panel.js`。

然后在 Chrome 里：

1. 打开 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选中 `extension/dist` 这个目录（不是 `extension`，是里面的 `dist`）
4. 扩展列表里出现 `chat-jev`，工具栏也会多一个图标

改了代码之后重新 `npm run build`，回到 `chrome://extensions` 点这个扩展卡片上的刷新按钮
（一个圆形箭头图标）让 Chrome 重新加载 `dist/` 里的文件。

## 开侧边栏

点工具栏上的 chat-jev 图标，Chrome 右侧会打开侧边栏。侧边栏跟着「当前窗口」走，
切标签页时侧边栏内容会自动刷新到新标签页对应的状态（不需要重新点图标）。

## 在某个站点上启用

出于隐私和安全考虑，这个扩展**默认对任何网站都不做任何事**——不读、不注入一行脚本。
清单文件里申请的是 `optional_host_permissions`（可选权限，装上不生效、要你点头才给），
而且只列了五个目标站点：

`web.whatsapp.com`、`web.telegram.org`、`app.slack.com`、`discord.com`、`teams.microsoft.com`

**不是「访问所有网站」**：这五个之外的站点，扩展连权限都申请不了，侧边栏上的
「Enable on this site」按钮是灰的。要加站点，得改 `manifest.json` 再重新加载扩展。

要在某个聊天网页上用起来：

1. 打开你要用的聊天网页（比如 WhatsApp Web、Slack 网页版），且这个标签页是当前激活的标签页
2. 打开侧边栏，顶部会显示这个网站的域名，旁边一个「Enable on this site」按钮
3. 点它，Chrome 会弹出系统权限确认框，问你是否允许这个扩展访问这个网站——同意
4. 同意后按钮变成「Enabled」，说明内容脚本已经开始读这个页面

同意之后，这个网站以后每次打开（新标签页、重新加载、重启 Chrome）都会自动生效，
不需要每次都重新点一遍「Enable」——但这只对**你已经明确同意过的网站**成立，
没同意过的网站永远不会自动跑一行脚本。

如果想收回权限，在 `chrome://extensions` 打开这个扩展的详情页，「网站访问权限」里可以移除。

## 填 API key

侧边栏往下滚，「Settings」是一个可展开的区块，里面两组字段：

- **Jev**：接 TypeSafe 的云端判断服务（key / base URL / model）
- **Generic LLM (OpenAI-compatible)**：任何 OpenAI 协议兼容的服务，比如 DeepSeek
  （key / base URL / model）

两组 key 都留空的话，侧边栏会显示「no API key configured」，不会假装分析出了结果。
两组都填了的话，Jev 优先（跟桌面版 Python 应用同一个规则）。

key 输入框是密码框（`type="password"`），不会明文显示在屏幕上。填完点「Save」，
存在 Chrome 本地存储里（`chrome.storage.local`），不会同步到 Google 账号，也不会发到
本项目作者的任何服务器——直接从你的浏览器发给你在这里填的那个服务商。

语言下拉框（`en` / `中文`）决定判断层用哪一套意图/风险提示词，默认 `en`。

## 诊断视图：怎么帮我们把这个站点做好

**诊断只含页面结构，不含任何聊天内容，可以安全分享。** 具体来说，它是：
消息容器用的是什么标签和 class、有几条消息、消息节点下面几层是什么结构、
有没有找到输入框——所有原本可能是聊天文字的地方都会被替换成「长度是多少」这类脱敏信息，
不会出现你或对方说的任何一个字。脱敏覆盖的范围：

- `aria-label` / `aria-description` 与除 `data-testid` / `data-qa` 之外的全部 `data-*`：值一律换成长度
- class 名、元素 id、诊断里那串「选择器」本身、以及其余结构属性的值：只有长得像普通 CSS
  标识符（字母数字 `_` `:` `-`）、不超过 64 字符、且不含连续 7 位以上数字的才照抄，
  其余换成长度。最后那条是为了挡住 `#chat-with-15551234567` 这种把电话号码写进 id 的站点

用法：

1. 打开一个已经启用的聊天网页，侧边栏「Diagnostic」区块展开
2. 如果扩展在这个站点认不出消息（没读到消息、方向判断不出来），这里会直接显示出来，
   而不是像现在的桌面版那样卡在「等待消息」让人猜发生了什么
3. 点「Copy diagnostic」把这段 JSON 复制到剪贴板
4. 贴到 issue 或者发给写适配器的人——这就是下一步给这个站点写专用解析逻辑的原始材料

「Refresh」按钮会让它重新读一次当前页面的结构（比如你手动改变了页面布局之后）。

## 刷屏保险丝

一个会话一分钟内新消息超过 20 条，侧边栏顶部会出现黄色提示条，自动分析暂停，
点「Resume」恢复。这是防止群里刷屏时疯狂调用后端。

## 已知限制（第 1/2 期）

- 只分析当前激活的标签页；切到后台的标签页只是继续读页面，不会触发判断
- 目前只有通用启发式适配器，方向判断（谁发的）在很多站点上不可靠——`isSelf` 判不出来的
  消息永远不会被当成「该回复的那条」，这是刻意的保守规则，不是漏洞
- **消息容器可能选中左边的会话列表**：找容器的启发式是「哪个元素的同形状子节点最多」，
  而会话列表也是同形状重复结构，而且行数常常比打开的那个会话还多。带明确
  `role="log"` 的站点会优先选中真正的消息区；没有这个属性的站点就可能选错，
  于是「消息」读出来是联系人预览文本。诊断视图的 `candidateContainers` 列出了全部候选，
  第一条就是被选中的那个——选错了一眼能看出来，也正是写专用适配器要解决的第一件事
- **WhatsApp Web 上切换会话检测不到**：作废在途结果、重置去重与保险丝，靠的是 URL
  （path + query + hash）变化。Telegram（hash）、Slack、Discord、Teams（path）都会变；
  WhatsApp Web 切会话时 URL 恒为 `https://web.whatsapp.com/`，没有任何可读的变化，
  所以在 WhatsApp 上切会话时上一个会话的在途判断不会被作废、顶部标题也不会更新。
  不拿标题之类的东西凑数：标题会因为未读数闪动而变，那只会造成假的会话切换
- 没有「一键填入候选回复」——这期只到「告诉你该怎么回」，动手填字是以后的任务
- 扩展的分析状态存在内存里（Chrome Service Worker），Chrome 在你长时间不用时可能回收它；
  回收后再有新消息会重新开始判断，不影响正确性，只是可能重复判断一次已经判断过的消息
- 只验证过单窗口场景；如果你同时开两个 Chrome 窗口各看一个会话，两边可能会互相干扰

## 隐私

- 消息文字只在你本机的浏览器和你在 Settings 里配置的服务商之间传输，不经过本项目作者的
  任何服务器
- 日志、诊断视图、面板上的任何状态文字都不含消息正文——参见上面「诊断视图」一节的说明
- 只读 DOM，不调用任何聊天平台的官方 API，不修改页面，不自动发送任何消息
